# 云更新怎么用（大白话版）

一句话：**以后改 App，不用再把安装包传来传去了**。改完在电脑上推一下，手机自己就换上新的。

现在的版本号是 **9.1.2**，以后每推一次更新就 +1（9.1.3、9.1.4……），手机上直接能看到。

---

## 一、手机上会看到什么

打开 App → 最下面「我的」→ 找到「**版本与更新**」：

| 看到什么 | 什么意思 | 点哪里 |
| --- | --- | --- |
| 当前版本 9.1.2 | 现在手机上是哪一版 | —— |
| 原生底座 9.1.2 | 安卓本身那一层（只有重新装安装包才会变） | —— |
| **有新的更新包** | 只改了界面、文字、菜谱内容、推荐逻辑的那种更新 | 点「下载这个更新」，下完点「马上重启」，就是新版了 |
| **要装一次新的安装包** | 这次动到了安卓本身（加权限、换原生模块），必须重装 | 点「下载并安装」，系统会弹安装界面，点「安装」 |
| 已经是最新版 | 服务器上没有更新的了 | —— |

不用天天去点：**每次打开 App、以及每次从后台切回来，它都会自己悄悄问一次服务器**（一小时最多问一次），
有新包就在后台下好，**下次打开 App 自动就是新版**——全程不弹窗、不打断、不用点任何东西。
上面那个面板只是让你想立刻换新版时用的（点「马上重启」）。

只有一件事它不会自己干：**不会在你用着的时候突然重启**。手机上那份新版要等你下次打开才生效，
这也是为了别把正在填的东西弄丢。

**下载中途切到别的应用会暂停**（安卓会把后台的 App 冻起来，这是系统的规矩）。不用管它：
回到这个 App 会**接着下**，已经下好的部分不会重来。所以最省事的用法就是——不用管，
下次打开自然就是新的。

## 二、电脑上怎么推

双击 `work\push-update.bat`，它会让你输入「这次改了什么」，然后自动干四件事：

1. 把**版本号 +1**（9.1.2 → 9.1.3）；
2. 把当前的 JS 打包；
3. 传到服务器（`YOUR_SERVER_IP`）；
4. **自己验一遍**：装成手机去问服务器要更新，把服务器发出来的每个文件都下一个遍，逐个核对哈希。

也可以直接跟我说「推一个更新，说明写 xxx」，我来跑。

## 三、版本号的两层（有点绕，但很重要）

App 里有**两个**版本号，别搞混：

**① 版本号**（`app.json` 的 `version`，比如 9.1.2）

- 就是面板上显示的「当前版本」；
- **每推一次更新都 +1**，不管是云更新还是重装包；
- 推更新的脚本会自动帮你 +1，不用手改。

**② 原生底座**（`app.json` 的 `runtimeVersion`，现在也是 9.1.2）

- 代表安卓原生那一层（权限、原生模块、安卓工程配置）；
- **平时绝对不要动它**，只有重新打安装包的时候才跟着改；
- 为什么：云更新的客户端靠它判断「这个更新包适不适合我」。它要是跟着版本号一起涨，老手机上就永远收不到更新了——所以脚本会拦住 `appVersion` 那种写法。

一句话：**只改界面 / 文字 / 菜谱 / 逻辑 → 什么都别管，直接推。**

---

## 四、什么时候需要重装安装包

只有动了安卓原生部分才需要：加权限、加原生模块、改 `app.json` 里的 `plugins`。这时候：

1. 把 `app.json` 的 `version` 和 `runtimeVersion` **一起**改成一个新号（比如都改成 `9.1.9`），`versionCode` 改成 `90109`（规则：大版本×10000 + 中版本×100 + 小版本）；
2. 同步源码 → `prebuild` → 打包，得到 9.1.9 的安装包；
3. 上传：`node work\publish-update.mjs --apk-only --note "..." --apk "<安装包路径>"`。

（这些步骤目前由我来跑，你说一声就行。）

## 五、东西都放在哪

| 位置 | 是什么 |
| --- | --- |
| 服务器 `C:\backend\updates\<原生底座>\<时间戳>\` | 每一版更新（JS 包、图片、元信息），一版一个目录，旧的不会删 |
| 服务器 `C:\backend\apk\` | 最新的安装包 + `latest.json`（版本号、大小、哈希） |
| 浏览器打开 `http://YOUR_SERVER_IP:8080/updates` | 状态页：每个原生底座当前会发出去的更新是什么、什么时候发的 |
| 电脑 `work\publish-update.mjs` | 发布脚本本体 |
| 电脑 `work\push-update.bat` | 双击就能用的入口 |
| 电脑 `<项目根目录>` | 源码（发布脚本读的就是这里） |

## 六、常见问题

**改了代码推上去了，手机上还是老样子？**
先在「版本与更新」面板点「再检查一次」。还是没变，看「正在运行」那行：写着「安装包里自带的」说明还没下到新包，写着「下载来的更新包」说明已经是云更新后的版本了（配合「这一版的时间」和「当前版本」一起看）。

**推完更新，手机上显示的版本号没涨？**
版本号是打进那份 JS 里的，要**更新生效之后**才会显示新号（下载完还得重启一次）。

**手机提示连不上更新服务器？**
更新走的是 `YOUR_SERVER_IP:8080`，跟共享清单同一台服务器。服务器活着、手机有网就能连上。

**下载完点安装，系统拦住了？**
Android 第一次安装自己下的安装包，需要允许 App「安装未知应用」。面板上会直接给一个「去允许安装未知应用」的按钮。

**想回退到上一版怎么办？**
把旧代码推一次就行（版本号会比现在更高，但内容是你想要的旧内容）。别去删服务器上的目录——客户端发现「服务器给的比我现在的还旧」时会拒绝，反而更乱。

**一次更新手机要下多少流量？**
图片这类资源是按内容命名缓存的，没变的不会重复下。只改代码的话，一般就是 2～3 MB 的 JS 包。
