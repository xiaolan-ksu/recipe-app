# 微信小程序迁移评估

> 2026-10-13 评估。结论：**技术上可行，但存在三个我方无法解决的硬前提，且不是"一键发布"。**
> 本文档基于对当前代码的实际测量，不是估计。

## 一句话结论

这不是"把 App 推上去"，而是**新建一个工程**：逻辑层约 39% 可以搬，界面层约 61% 必须重写。
能不能真正上线，主要取决于**你有没有一个已备案的 HTTPS 域名**，而不是代码写得多快。

## 三个硬阻塞

### 1. 需要小程序 AppID（只能你本人办）

要在 [mp.weixin.qq.com](https://mp.weixin.qq.com) 注册小程序，个人或企业主体，需实名。
拿到 AppID 才能上传代码、提交审核。这一步无法代办。

### 2. 微信强制要求 HTTPS + 已备案域名（最关键）

当前后端是 `http://YOUR_SERVER_IP:8080` —— **IP + HTTP**。微信小程序**不允许**：

| 要求 | 当前状态 |
| --- | --- |
| 必须 HTTPS | ❌ 443 端口不通，`https:8080` TLS 握手失败 |
| 必须是域名，不能是 IP | ❌ 现在是裸 IP |
| 域名必须已完成 ICP 备案 | ❌ 未备案 |

备案通常需要 **1–3 周**。建议：**先去办域名和备案，同时我并行写代码**，备案下来直接接上。

如果确实不打算备案，只能做一个**纯本地版**小程序（菜谱浏览、推荐、忌口全部可用，
但"共享清单"这个双人同步功能做不了，因为它依赖后端）。

### 3. 需要安装微信开发者工具

上传代码必须要它，当前这台机器上**未安装**。

## 两个技术现实

### 图片体积超标（必须处理）

| 项目 | 数值 |
| --- | --- |
| 菜品图片 | 117 张，共 **23.44 MB** |
| 平均 / 最大 | 205 KB / 864 KB |
| 小程序分包总计上限 | **20 MB**（部分类目可申请 30 MB） |

**光图片这一项就超过了总计上限**，必须把图片搬到对象存储 / CDN，以 `https` 外链引用，
或大幅压缩后分包。这一步无论如何都省不掉。

### 代码要重写 61%

| 部分 | 行数 | 占比 | 能否复用 |
| --- | --- | --- | --- |
| 数据 / 逻辑 / store（`data` `lib` `store`） | 4384 | 39% | ✅ 基本可直接搬 |
| 界面层（`screens` `components`） | 6720 | 61% | ❌ 必须重写 |

界面层不能复用，因为 React Native 组件和小程序组件是两套东西
（`View`/`Text`/`Pressable`/`FlatList` → `view`/`text`/`button`/`scroll-view`），
样式、导航、手势也都不一样。

## 小程序里不存在的能力（都要替代方案）

| 现在用的 | 问题 | 替代方案 |
| --- | --- | --- |
| `expo-updates` | 小程序没有 OTA 概念 | 用微信自己的版本发布流程 |
| `expo-intent-launcher` | 小程序没有"安装 APK"这回事 | **整块功能删掉**（版本更新面板） |
| `expo-file-system` | 小程序无 Node 式文件系统 | `wx.getFileSystemManager` |
| `expo-image-picker` | — | `wx.chooseMedia` |
| `expo-location` | — | `wx.getLocation`（且需申请类目权限） |
| `expo-blur` | 小程序样式能力有限 | 用半透明纯色近似 |
| `react-native-svg` | 小程序不支持 | 改用 `canvas` 或图片 |
| `@react-native-async-storage` | 小程序无 localStorage/AsyncStorage | `wx.setStorageSync` / `wx.getStorageSync` |
| 自建后端共享清单 | 需 HTTPS 域名 | 保留，但前提是域名备案完成 |

`zustand` 状态管理可以在小程序里继续用（纯 JS 库）。

## 三条可选技术路线

| 路线 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| **Taro**（推荐） | 用 Taro 保持 React + TypeScript 语法 | `store`/`lib`/`data` 这 4384 行几乎直接搬；两端长期可同步维护 | 需装 Taro 工具链，个别 API 要适配 |
| 原生小程序 | 用 WXML/WXSS/JS 重写 | 性能最好、坑最少 | 4384 行逻辑也得跟着改成 `wx` 风格，工作量大幅增加 |
| web-view 套壳 | 把现有网页版嵌进去 | 最快 | 需企业主体；体验差；定位/相册等能力受限 |

## 建议的推进顺序

1. **你**：注册小程序拿 AppID + 办域名与备案（周期最长，先启动）。
2. **我**：用 Taro 新建工程，搬 `data` / `lib` / `store`，把 `expo-*` 依赖逐个替换成 `wx.*`。
3. **我**：重写界面层，先做首页 + 菜谱页 + 详情页（核心链路），再做食材/买菜/我的。
4. **图片**：压缩或迁 CDN，控制分包体积。
5. 用测试号在开发者工具里跑通，换正式 AppID 后上传、提审。

## 需要你确认的三件事

1. **AppID**：已有 / 还没注册（可先用测试号开发）？
2. **域名**：有已备案域名 / 有域名未备案 / 完全没有？
   - 若"完全没有"：先做纯本地版，还是等备案？
3. **技术路线**：Taro（推荐）/ 原生 / web-view？
